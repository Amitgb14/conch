# Compared

conch is one of several tools for running coding agents side by side. The three it is most often weighed against are [herdr](https://herdr.dev), [T3 Code](https://github.com/pingdotgg/t3code) and [Orca](https://orca.dev). Each takes a different shape:

- **herdr** is closest to conch: a server that owns the terminals, a tmux-style TUI, and ssh machines that install it themselves. It is written in Rust.
- **T3 Code** drives agents through their SDKs (Claude's Agent SDK, the Codex app server, ACP) and shows them as chat threads, on the desktop, the web and phones.
- **Orca** is a desktop IDE built on Electron around worktrees: agents in terminals or a chat view, an editor, diffs, pull request review and a browser.

As of November 2026, from each project's own documentation. All three ship often, so check their docs for anything that matters to you, and [open an issue](https://github.com/Amitgb14/conch/issues) if something here has gone out of date.

## When to choose another

- **You want a graphical review.** T3 Code and Orca review pull requests in full — threads, reactions, stacks, more forges than GitHub. conch's review is the diff and the hunk, and leaves the conversation with other people to your forge.
- **You want a chat, not a terminal.** T3 Code shows each agent as a conversation with structured approvals; conch shows the agent's own interface, as you would see it without conch.
- **You are on Windows.** herdr, T3 Code and Orca build for it; conch is macOS and Linux, and WSL.
- **Your agent is not one of conch's five.** herdr and Orca know many more agents. conch [runs others](/docs/agents#supported-agents) from a manifest, without reading their saved conversations.
- **You want native phone apps.** T3 Code and Orca have them, with their own hosted relay. conch's phone page is reached through a network you already have.

## When to choose conch

- **You want the loop closed without you.** conch's server sends a failed check or CI run back to the branch's agent and merges once it is green, with no window open — the step the others leave to a button or to you.
- **You want agents to drive agents, and stay in their lane.** `conch mcp` and the CLI let one agent start, prompt and read another, and an agent calling from its pane reaches only what it started and its own project.
- **You want agents in the cloud.** A sandbox is a machine like any other: conch makes it, installs itself there, and stops it when you say.
- **You live in a terminal, often over ssh.** The TUI is conch, not a fallback, and a reload onto a new build keeps every agent running.
- **You want nobody else's server between you and your phone.** The phone reaches conch through Tailscale or a relay you run, encrypted end to end.
