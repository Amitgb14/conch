# Mac app

Conch.app is conch in a native macOS window. It is another client of the same servers the TUI talks to — this computer's and every machine you added — so it shows the same agents and terminals, and closing it stops nothing: the agents keep running, as they do when you close the TUI.

<Callout type="note">

The Mac app is in **beta**: download it from the release (below), or build it from source. A few things are still the TUI's alone: syncing one agent's setup to another and the library, your own folders in the tree, a project's check and the server's scheduled tasks in the review queue, and the settings that are tables (actions, permission rules, sandbox providers). **conch → Open conch in a terminal** opens the TUI beside the window.

</Callout>

## The window

- **The toolbar** holds conch's workspaces (click one to switch; `+` makes one, as in the TUI, which shows it too; double-click or right-click one to name it — `1 main  2 review` — which the TUI shows as well; right-click → **Close Workspace…**, the **×** that shows with the pointer on one, or **File → Close Workspace…** for the one on screen, on any but the first, closes it as the TUI's `ctrl+b X` does, its projects, machines, hosts and tabs going to workspace 1 and what runs only in it moved there or ended, as you choose) — each isolated as in the TUI, with tabs of its own and only what is in it: its projects, the panes started in it and what those started, and in the first whatever no other workspace has; an agent or terminal started from the app goes into the workspace on screen, a search field in the middle (⌘K), and how many agents in that workspace are waiting for you or finished, dimmed at none rather than gone — a click on the waiting count goes to the next one (⌘.), and on the done count to the next agent that finished — then **N to review**, the TUI's review queue counted on every machine: agents waiting or finished, branches whose pull request's CI failed, with commits not pushed or merged, or with uncommitted work and no agent on it, leaving out rows dismissed in the TUI. A click lists them, the most urgent first; a row opens its agent or the branch's changes. **Fix**, on a row whose pull request's CI failed, sends the failure to the branch's agent (or starts one in its worktree with it), as `f` does in the TUI's queue (`conch branch fix-ci`); **✕** dismisses a row until it changes, as `x` does — kept in `ui.json`, so the TUI leaves it out too. A row's right-click menu has the same. A project's own check and the server's scheduled tasks are in the TUI's queue only.
- **The sidebar** is conch's tree: this computer, then each machine you added (`conch machine add`), each with its projects under **Workspace**, as in the TUI — agents, branches, terminals and how many saved sessions — and **CLI** for what belongs to no project. The Workspace row folds as the TUI's does, and its menu starts a task in any of its projects. Each agent is marked as the TUI marks it, following the same `[ui] icons`: with `icons = "nerd"` the TUI's glyph in the agent's own colour (Claude's asterisk, Codex's six-fold mark…) from a Nerd Font on the Mac, or an SF Symbol of the same shape without one; otherwise a dot in the agent's colour, the mock's, or nothing for `off` and, at the right, its branch (muted, as the TUI's row has it, cut in the middle when it is long) and a pill while it is **working** (with the TUI's spinner turning in it), **waiting** for you or **done**; a tab with an agent at work shows the spinner beside its name; a pane that ended says **exited**. A machine or project row counts what is working (blue), waiting (amber) and done (green) in pills; the tree's icons are Lucide's, the outlines shadcn/ui draws: this computer a laptop, another machine a server and a sandbox a cloud, each with its state as a dot on the corner (green online, amber connecting, grey not there); a project a folder, open while it is; a branch git's branch, in the accent when it is checked out in a worktree of its own, muted when not, with its pull request and how far ahead it is; a terminal `>_`, an ssh session a globe; CLI a terminal in a box; Workspace layers; Sessions a history clock. The pane you are in is the row with the accent behind it, and the row under the pointer is tinted. Another machine is reached as the TUI reaches it, through [`conch machine bridge`](/docs/cli#machine); one that cannot be reached says **offline**, with why on hovering, and is tried again every half minute. A sandbox is listed with its provider (`sandbox · daytona`) and says **stopped** while it is; the app never starts one by itself and looks again every five minutes. Its row's menu starts it (**Start sandbox**), stops it (**Stop sandbox…**, after asking: its agents and terminals stop with it), says **What it has cost** period by period, and deletes it for good (**Delete sandbox…**, after asking) — each `conch sandbox` with its provider. Rows fold as they do in the TUI — the same rows open, read from its `ui.json` — and what you fold or open here is remembered by the app without changing the TUI's. A folded machine shows the dots of the agents on it. A project lists the branches the TUI lists: the main checkout's first, those checked out in a worktree, the base and those a pane works on, then up to twelve committed to in the last two weeks; the rest are counted in a **… N more** row, which lists them all when clicked, and **Show fewer** puts them away again. A click opens a pane; a click on a branch opens its changes (below). Drag the sidebar's edge to make it wider or narrower; the width is remembered.
- **Notifications.** When an agent comes to wait for an answer or finishes and you are not looking at it, Conch.app posts a notification — a click on it opens the agent — and the Dock icon carries how many agents are waiting, on every machine, bouncing once when one starts waiting while the app is in the background. It follows `[notify]` in config.toml as the TUI does: `enabled`, `desktop`, `sound`, `waiting`, `done` and the `quiet_start`/`quiet_end` hours. With a TUI open on that machine the notification is left to the TUI, so it is not said twice. macOS asks once whether conch may post them (System Settings → Notifications); where it may not, the system's own notification is shown instead.
- **Marks and icons.** Agents are marked by their own logos — Claude, Codex and Gemini from Simple Icons; Grok, Devin, Amp, Kilo Code, OpenCode and Cursor from LobeHub's icons — filled in each agent's colour, or in the theme's text colour where that would vanish into the background (Grok's white on a light theme), in the tree, the tabs and the pane headers. An agent with no logo there (Aider, Pi, your own) keeps the mark `[ui] icons` gives it, and `icons = "off"` shows none. Agents, Branches and Terminals each have an icon, as Files and Sessions do.
- **What a row says.** A branch says what the TUI's does, part by part: its agents' state (`!` waiting first), conflicts (`⚠2`) or its uncommitted changes (`+3 −1`, or `~4` files), its pull request (`#7✓` passing, `#7✗` failing, `#7●` pending, merged in purple, `×` closed, a draft muted), and `gone`, or how far it is ahead of and behind the base (`↑2↓1`; the base itself against its upstream, `⇡1⇣2`). A pane that ended says how — `exited`, or `exit N` and `failed` in red — and a terminal watched for it carries `# output` or `~ quiet`. Watch one from its menu — **Alert when it goes quiet** (for `[notify] silence` seconds after printing, 30 by default: a build or a test run ending) or **Alert on output** — as the TUI's `ctrl+b M` and `A`; an alert raised while you are looking elsewhere is also a notification, and looking at the pane clears it.
- **What agents spend.** Each agent's row, and the machine, project and Agents rows for what they hold, carry what the agents have spent as the TUI's do — a cost where the agent reports one (Claude Code and OpenCode), else the tokens written (`42k out`), else read — and an agent's pane header says its context against the model's window, its output and cost (`ctx 45k/200k · out 1.2k · $0.42`). Only what conch has seen is counted. `[ui] cost = false` turns it off here and in the TUI.
- **Helpers and subagents.** A pane an agent started — a helper it handed work to — is listed under that agent, and so is each subagent it runs in its own process (Claude Code's Agent tool, a spinner and the task it was given), as in the TUI. The arrow folds them; a click on a subagent shows its agent, since it has no screen of its own. A section's count is every pane in it, the nested ones included.
- **Find in a pane.** ⌘F opens a find bar over the focused pane. Return looks back through its whole history for the text and brings the match into view with every match on screen marked, as `/` does in the TUI's scroll mode; ⌘G looks further back and ⇧⌘G forward again. A query in lower case matches either case. Esc closes it and clears the marks. Shift-Page Up and Page Down scroll a pane's history from the keyboard, and shift-Home and End go to the top and back.
- **Links.** ⌘-click a link a pane printed — an agent's login URL, a dev server's address — to open it in your browser; web and mail links only, never `file:` or a custom scheme. A plain click still goes to the program, as before.
- **Dropping files on a pane.** Drag files from the Finder (or an image from a browser or a screenshot's thumbnail, which is saved as a PNG first) onto a pane and their paths are pasted into it, escaped as Terminal escapes them — what an agent needs to read a screenshot. On another machine's pane the files are copied there first (`conch -m MACHINE upload`, into its uploads folder) and the paths they landed at are pasted instead, as the TUI does with a drop.
- **On opening**, the window shows the tabs the TUI is showing (each machine's, as its server keeps them), a tab of three panes as one tall beside two stacked — and gives none of them the keyboard, so no key reaches an agent until you click a pane.
- **Tabs** along the top, the one on screen underlined, each with its number for `⌘1`–`⌘9` and **⊞** when it holds more than one split. Drag a tab onto another to move it there; double-click one, or right-click → **Rename Tab…**, to name it (an empty name goes back to naming it by its pane) — a tab taken from the TUI keeps the name the TUI gave it. A pane is shown in one place: opening it again goes to where it is. A pane whose program exits on its own — a shell's `exit`, an ssh logout, an agent's `/exit` — closes, and its split or tab with it, as in the TUI; one that fails in its first seconds stays, so its error can be read. **Settings → Mac app → Tabs** (`[app] tabs`) puts them down a side instead: on the **left** they sit at the top of the sidebar, grouped under each machine (*This Mac*, then each machine by name) with the tree below them, so a tab on another machine reads as one before it is opened; on the **right** they are a column of their own. Down a side each row is a tab — its number, its agent or kind, its name, **⊞** and the number of its splits, and what the agents in it are doing: a spinner while one works, an amber dot while one waits for you, ✓ when one has finished — and the line above the splits says which tab is on screen and where.
- **Splits** sit side by side as cards with a gap between them, each with a header saying which agent it is, its branch and its state — with how long it has been working. A terminal in a checkout that has been given ports shows the first, `CONCH_PORT` (`:4317`); on this computer a click opens it in a browser tab, ⌥-click in your own browser. The focused one has the accent border. Drag the gap between two splits to resize them; ⇧⌘↩ zooms the focused split to the whole tab and back, and ⌥⌘ with an arrow moves the focus to the split that way. The tab bar ends with where the tab on screen is (`api · local`). A pane whose programs listen on a TCP port — a dev server started there, however deep under the shell — shows it in its header (`:4317 ↗`, found every few seconds by the server, `pane.listening.v1`), taking the place of `CONCH_PORT`; a click opens it in a browser tab beside the agents (⌥-click: in the browser you use), and on another machine copies the ssh tunnel that brings it here (`ssh -N -L 4317:localhost:4317 host`). **Settings → Mac app → Ports in pane headers** turns them off. With **Density** compact the header is shorter and the splits sit closer.
- **The status bar** says where the keyboard is (**PANE**, or **TREE** when no terminal has it) and the keys for there, each as a keycap — or, for a few seconds, what was just done or why it could not be (a failure in red; a click puts the keys back), and while a long job runs (a reload, an upgrade, a push) what it is doing beside a spinner. Closing a split that holds a working agent says the agent goes on running and where to find it: a split or tab closed in the app only hides its panes; each agent plan's use, as a chip with the agent's mark and each window's bar and share (`✱ 5h ▰▱ 36% │ 7d ▰▱ 19%`, amber from 80%, red at the limit; when each resets is in its tooltip) — a click lists every window the agent reported, the 5 hours, the week and any per-model one, with when each resets; **✦ Ask**, conch's brain bar — a request in plain words, its plan shown, and nothing run until **Run** (it is `conch ask`, answered through its own confirmation, so what runs is the plan shown); **⊙**, report a problem — the facts `conch bug` gathers, never a path or a screen, and **Open a GitHub issue** with them for you to read before submitting; the phone, pair a phone — a one-time code with its QR code (`conch web pair`), **Full**, **Reply** or **View** for what it may do, and **Start it** when the gateway is not running (`conch web start`); conch's version, with which terminal draws the panes in its tooltip; **⚙ Settings** (or **conch → Settings…**, `⌘,`), which opens conch's settings in a panel of the app's own — the [settings page](/docs/interface#edit-in-browser)'s sections down the left with their icons and the chosen one's settings on the right, switches, menus and fields drawn from the same schema and saved through the same page (`⌘S`; a file changed meanwhile is read again rather than written over; an open TUI takes in what you save, and the app's theme follows it unless you picked one). Actions, permission rules and sandbox providers are tables, which the panel leaves to the file itself: **Edit config.toml** opens it in your text editor (the app never sends you to a browser for settings); and `▁▃▆` in the corner, the memory and CPU conch uses on this computer — the app, the server and each pane with everything running in it — sampled every two seconds while it is open, as the TUI's is. A pane repainted from conch's screen rather than drawn by Ghostty (an older server, or a build without Ghostty) says **repainted** there when it is in front; a pane Ghostty draws says nothing. The usage chip — or **Usage**, before any agent has reported its plan — opens the plan windows and below them **Tokens used**: for the last 24 hours, 7 days or 30 days, each agent's input, output and cache reads and writes, how many responses, and each model's share, read by each machine's conch from the conversations the agents saved, so sessions outside conch count too (`usage.history.v1`). When a machine's conch is older than the app's — it lacks something this build has — the version at the end of the bar turns warn-coloured and says how many are behind (**↑ v0.1.9 · 2**); a click lists each one (this Mac first) with what it lacks, ticked, and **Upgrade** reloads this Mac's server and installs this build on the others — built from conch's source on this Mac when the app was built here (it is told where `macos/bundle.sh` built it from), else the released binaries of its version. conch's version is at the very end, after **Settings**. The **conch** menu says under **Quit** how many panes keep running when the app quits.
- **Styles.** **View → Style** decides how the window is drawn, apart from its colours. **Standard** is the window described here. **Ink** draws it as a manga page: ink borders and square panels with white gutters, the focused one lifted off the page by a shadow in the theme's accent, screentone behind the sidebar and the status bar, the tab on screen and the focused pane's row in solid ink, waiting and done counts as lettering bursts, each agent's state lettered in its pane's header (a working one with its *tap tap*), and a waiting agent's question in a speech bubble, in its pane and in the sidebar's Needs you. Choosing Ink also chooses the Ink theme, black on paper, which it was drawn for, as **View → Theme** would; any theme can be picked after, since the ink is the theme's text colour, and a theme chosen in the Settings panel takes over from it (the window goes back to **Same as conch**). **Meadow** is hand-painted, after the anime films: a sky behind the toolbar (clouds and a sun by day; under a dark theme a night sky with a moon, stars and fireflies), warm paper in the sidebar, the rounded system face for the window's own text, rounder cards with a soft shadow and the focused one ringed in the accent, a leaf on the tab on screen, a waiting agent's question as a note with a dashed amber edge, in its pane and in Needs you, and a strip of grass along the status bar. Choosing it chooses the Meadow theme; its dark pair is Firefly, so `theme = "firefly"` with `light_theme = "meadow"` follows macOS between night and day. **Cel** is cel-shaded — flat fills, thick dark outlines and one hard shadow on every card — and lays the window out around the agents: every agent and terminal the workspace shows is a card in a roster across the top (its mark as a face, its project and branch, a bar and a word for its state, since when), what needs you first, then what is working, done, at rest, terminals and what has exited; a click opens it. A column of projects stands in for the tree — ☰ brings the tree back (⌃⌘S hides it again), **all** or a project's two letters narrows the roster — and on the right the longest-waiting agent's question is a dialogue box with its name tag and its answers, above a log of what the agents last did. Choosing it chooses the Cel theme. **Terminal** is the Standard window on a terminal's ground, after herdr: the same layout, tree, pills and teal accent, on ink black with dark hairline borders, every word of the window in the monospace face (SF Mono, a size smaller, so a label takes the room it did — except the tree's names and labels, which stay full size) and the sidebar 70 points wider for it, the title bar the window's own colour; choosing it chooses the Terminal theme, which the TUI has too, and while it is the theme a light Mac shows its pair, **Terminal Light** — off-white, grey hairlines, the teal deepened, a selected row solid teal with white words — and back to Terminal when macOS goes dark (Terminal Light picked by name stays light). Terminals keep their own font in every style. **Sizes.** **Settings → Mac app** has **Window text size**, in percent, for the window's own text (`[app] text_size`), and **Terminal font size**, in points, for every pane (`font_size`, 14 by default); **View** steps each with the keys in the table below, saving to `config.toml` as the settings page does, and every pane and label takes the new size at once. The style is the app's own, kept in its preferences; the TUI has no borders to draw this way.
- **Themes.** **View → Theme** has conch's twenty-eight themes, eight of them light (GitHub Light, Solarized Light, Catppuccin Latte, VS Code's Light Modern and Light+, and conch's own Ink, Meadow and Terminal Light; Meadow's night is the dark Firefly, a pair for `theme` and `light_theme`, Cel and Terminal are conch's own too; VS Code's Dark Modern and Dark+, with their light pairs, are taken from VS Code's own theme files, and like Terminal each follows macOS to its light one while it is the theme); themes of your own, files in `~/.config/conch/themes/`, follow under **Your Themes**, with any file that did not read said there and **Open Themes Folder** at the end ([Configuration](/docs/configuration#themes-of-your-own)), and `[ui] accent` goes over the theme in use, in the app as in the TUI; the Settings panel's **Theme** is a grid of them, each a small picture of the window in it; with the pointer on a card the app shows that theme — the main window and Settings itself — and moving off the cards puts it back, so you see one before choosing it. The first item, **Same as conch**, follows `[ui] theme` in conch's settings, so the window matches the TUI until you pick another; your choice is remembered. A theme colours everything, the terminals in the panes included. Agents draw for a dark terminal — Claude Code's own theme writes white text — so in a light theme each pane keeps a contrast floor: text too close to the colour behind it is darkened until it reads (Ghostty's `minimum-contrast`, 3 on a light theme). The SwiftTerm panes, used when Ghostty isn't built in, have no such setting.
- **Light and dark.** Settings' **Light theme**, below **Theme**, offers only the light themes and makes the app follow macOS: that theme while the system is light, the one above while it is dark, switching as macOS does, by hand or by the time of day. **Off**, the default, keeps the app on the one theme. It is `[ui] light_theme` in `config.toml`, and only the app reads it: the TUI keeps to `theme`. A theme picked under **View → Theme** stays put in either appearance.

Each pane is a real terminal running [`conch attach`](/docs/cli#attach), so an agent looks exactly as it does in the TUI or any terminal.

## Panes drawn by Ghostty

Where the pane's server can give it (`pane.raw.v1`), a pane's Ghostty is given the program's own output (`conch attach -raw`) rather than conch's screen repainted into it — as Rex does with the same library. Ghostty then is the pane's terminal for everything it draws: its scrollback, which the trackpad scrolls with momentum and a pill at the bottom says how far (**↓ 214 lines below · End**, a click back down); selection the way Ghostty selects (a word, a line, a block with option); images a program prints with the kitty graphics protocol; ⌘F, which is Ghostty's own search over its history, saying which match of how many. A pane opened after it started has its history replayed into Ghostty first, so the search and the scrollback reach what it printed before.

conch's server still keeps every pane's screen, since the TUI, the phone and an agent's state are read from it, and it still answers the program's questions, which are taken out of what Ghostty is given so the program is not answered twice.

A pane has one size, and the server settles it between everyone showing it: whoever typed into it last. While that is another window — the TUI, the phone, another Conch — the pane is drawn **letterboxed**: at its own size, from the top left, the rest dotted with a dashed edge where it ends, and *Sized 160×38 for another window · Take it* at the corner. A click on the dots or **Take it**, or typing in the pane, makes it this window's, at the size the window has room for. The terminal's own answers and the pointer just moving over it take nothing.

A machine whose server is older, and an app built without Ghostty's library, keep the repainted panes: the status bar says **repainted**, and history and search are conch's, as before.

## The scratch layer

**⌥Space** shows a shell floating over the splits, in the project on screen — in the branch's worktree when a branch's pane is in front, else the project's checkout, or the machine's home outside any project — and hides it again. It is an ordinary pane named **Scratch**: the tree lists it under the project's terminals (the TUI's too), it keeps running while hidden, through a reload and with the app quit, and **⌥Space** brings the same one back. **⌥⌘↩** docks it as a split beside the focused pane, **⌥⌘T** makes it a tab; a scratch pane already in a split or a tab is gone to rather than floated as well. **Settings → Mac app → Option-space anywhere** (`[app] scratch_key`) makes ⌥Space work with Conch in the background too, as Ghostty's quick terminal does — a system hot key, which needs no Accessibility permission.

**Help → Check conch…** runs [`conch doctor`](/docs/cli#doctor) on this computer and lists its checks — the server, the agents, git, gh, the terminal, the machines — each with how to fix it; **Check again** runs them again after you have.

## A branch's changes

A click on a branch opens it in a tab of its own, as `enter` on a branch does in the TUI. The header says the branch, the base it goes into and how far ahead of it, its pull request with its checks, what is uncommitted and what its agent is doing; **Overview · Changes · Graph** switches between three views of it, and ⋯ holds **Agent or terminal** (the branch's agent, or the terminal already in its worktree), **Push**, **Merge into main…** (the base: squashed or as a merge commit, where the base is checked out; a merge that conflicts is undone and nothing changes), **Open pull request** (or update it) and **Delete branch…**, after saying what that would lose. A branch with changes — uncommitted, or committed and not yet in the base — opens on Changes; one with none on Overview.

**Overview** says whether the branch is clean and how it stands against its upstream (`master is up to date with origin/master`), with its last commit. A branch with a pull request has a card for it: whether it merges — **Conflicts with main in …**, naming the files from the server's own trial merge where GitHub only says it conflicts; that trial merges with the base as it is on your computer, so when your base has commits not pushed and GitHub finds the pull request clean, a collision with those alone is an amber note instead — **your local master (4 commits not pushed) would conflict in …** — with nothing to resolve until the base is pushed — its checks as they run (**3 of 5 done**, with a bar) and each one by name — failing first, then running, then passed, each linking to its run on GitHub — and the review's decision, with **Open on GitHub**. **Ask *agent* to resolve** hands a conflict to the branch's agent — merge the base in (not rebase: the branch is pushed), resolve keeping both sides, test, commit and push, and ask rather than guess — starting one in the branch's worktree when no agent is running there, and when the branch is checked out nowhere — a pull request's branch made on another computer — checking it out in a worktree of its own first (GitHub's copy, if it is not here at all); **Send the failure to *agent*** sends failed checks, as the review queue's **Fix** does. The header's pull request chip says **conflicts** in red, and beside it the checks in a few words — **CI running 1/3** with the spinner, **CI failing · 1 failed**, **CI passed 3/3** — in every view; in the graph the same chip marks the commit the checks run on, and the Changes view's **Checks** card, above the review, lists them too. A server before this build sends the counts without the names. Work handed over this way is followed in a strip under the header, in every view: **claude is resolving the conflict with main**, with the spinner, while it works; **waiting for you** with **Answer claude** when it asks something; **finished — check the result** once it is done, or gone if its pane closed; **Open claude** goes to it and **Dismiss** clears the strip. The header's agent is then the one the work went to, else one at work on the branch. Then the branch's recent commits (a click opens one in the graph); who changed it in the last week and how much of it; how far it is behind and ahead of its upstream and its base; its commits a day over the last fourteen (click a day for its count); and the project's other branches against the base, each with its pull request — a click opens that branch.

**Changes** has three columns. On the left:

- **Uncommitted** — what is changed in the branch's worktree and not yet committed (`M` changed, `A` added, `D` deleted, `?` new and untracked, `U` a conflict), each with its `+`/`−`, how many comments are on it, and a dot while the agent is writing it.
- **Committed on the branch** — what its commits change against the base, for a branch with a worktree.
- **Commits** — the branch's commits.

In the middle, the file's diff hunk by hunk, unified or split side by side, with line numbers; while an agent works in the worktree the open diff reads again. Each uncommitted file and each hunk has a box: tick a file for all of it, or hunks for part of it (the file's box then shows a dash). The box in the **Uncommitted** heading ticks every file, or none, and shift-click on a file's box ticks the run from the box you clicked last, as in Finder; and **Commit** commits only what is ticked. **Stage** is `git add`: it puts what is ticked in the index without committing it, and the file is marked staged — a green check, or a half circle when only part of it is; right-click a file to stage or unstage it whole. With nothing ticked, **Commit** commits what is staged, as git does, and when nothing is staged either, every change. Staging needs `branch.stage.v1` on that machine's server, and committing part of a file `branch.hunks.v1`.

Hover a line and press **+** to comment on it — a line of the new file, so a removed line takes none — then **Add note for the agent** (or ↩; ⇧↩ is a new line) or **Add to PR review**, which is there while the branch has an open pull request. A comment is either

- **a note for the agent** — kept by conch on that line (the TUI's review, `review.comments.v1`), so every client sees it; **Send** hands every open note to the agent you pick from the branch's agents, or to a new one started with them (`review.send.to.v1`; an older server picks the oldest agent not waiting on you), and each stays on its line as **sent to** that agent. The agent is asked to answer each in a sentence — what it changed, or why it left it — with [`conch review reply`](/docs/cli#review), and the answer appears under the note as it comes, marked **answered by** the agent; one that finishes without answering says so, and **Open *agent*** goes to its session either way. **Reply** answers back: the note waits to be sent again with its thread. Sent notes are kept by the server (`review.thread.v1`) for 30 days, or until resolved; against an older server they are the app's and last while the tab is open. **Resolve** drops one; or
- **a comment on the pull request** — it waits in your review until you submit it. GitHub's own comments on the pull request show on their lines too, with a link to reply there.

On the right, the commit: the message (**✦ Write** drafts it from what is ticked, or from everything, with the brain set in Settings, by [`conch commit-message`](/docs/cli#commit-message)), and a box to credit the branch's agent with a `Co-Authored-By` line. Below it the review: the notes for the agent, and for a branch with an open pull request **Approve**, **Request changes** or **Comment**, a summary, and **Submit review**, which sends it with its waiting comments through `gh` (requesting changes also sends the notes to the agent). Approving needs nothing else; requesting changes or commenting needs a summary or a comment. Then the pull request's checks. Submitting needs `pr.review.v1` on the machine's server.

**Graph** is the project's [commit graph](#commits), in the tab.

## Agent setup

**Agent setup** on a project's menu (or **Agent setup here** on a checked-out branch's) opens what each agent loads in that checkout, as the TUI's `i` view: its instructions, skills, MCP servers and the rest, each with where it comes from (`user`, `project`, `local`, `plugin`…), anything named but missing in red, and what conch noticed about how they fit together. A worktree also lists the main checkout's local files it should have and whether it does. A file's path opens it in that machine's editor. It reads only: syncing one agent's setup to another, and the library, are the TUI's.

## Answering an agent without opening it

Every agent waiting for you is a card under **Needs you**, at the top of the sidebar — across every machine the workspace shows, the longest waiting first, as direction C of the design has it. A card says which agent it is, what it wants as a pill (**permission**, **question**), the question itself, where the agent is (its project and branch, and the machine when it is not this one), and its choices as buttons — *Allow*, *Always*, *Deny…*, or the options of a question, the one the agent's own cursor is on in amber. A click on a button answers: conch moves the agent's cursor there and presses Enter, exactly as the [phone](/docs/phone) does, and refuses an answer to a question that has changed since it was shown. A click anywhere else on the card opens the agent. The same buttons are along the top of the agent's pane. An agent whose choices conch cannot read off its screen offers **Open to answer** instead. conch reads numbered menus, numbered menus with a description under each choice (Claude Code's question tool), and menus without numbers (Claude Code's folder-trust question). The card is read again every couple of seconds while the agent waits, so it follows the agent: a menu drawn a moment after the agent started waiting shows its buttons once it is there, and Claude Code asking several questions at once — a tab each — shows each question in turn as the one before is answered, here or in the agent.

## Files and sessions

The **Files** row of a project, under its terminals as in the TUI, opens its main checkout in a tab of its own: folders opening as you click them, each file marked by what it is, as an editor's file tree does — its language's or tool's own logo in its brand colour (Python's for `.py`, Docker's whale for a `Dockerfile` or compose file, Go's for `.go` and `go.mod`, npm's for `package.json`, React's for `.tsx`, and some sixty more, from Simple Icons), else an outline for its kind (a picture, an archive, a secret, a spreadsheet, a README) — and each file and folder with its git status letter, beside the file picked in an editor — line numbers, the caret's line lit, the theme's colours for comments, strings, numbers and keywords (Go, Swift, TypeScript and JavaScript, Python, Rust, shell, C-like languages, JSON, YAML, TOML, Markdown), undo and the find bar (⌘F). A binary file is named rather than shown. Edit it and **Save** (⌘S) writes it (`fs.write.v1`); the file's row shows a dot and its bar says **edited** until then. Agents write in the same files, so a save is checked against the file as it was opened: if something wrote it meanwhile the save is refused and you choose — **Reload Theirs** (your edits go) or **Overwrite with Mine** (theirs go); with edits open, a change on disk is said in a banner instead of replacing them. Leaving a file or a branch with edits asks whether to save them. The branch beside the project's name switches the tab to any branch checked out in a worktree — an agent's, say — and editing then writes there; a branch with no worktree is listed but can't be picked, and the tab never checks a branch out in your main checkout. **Hidden files** lists dotfiles too, ↻ reads it again and turns while it does, and it reads again by itself when an agent writes in that checkout. A file too big to read whole (over 256 KB) is shown read only, as is everything on a machine whose conch predates `fs.write.v1`, which says to reload its server; one that predates `fs.files.v1` can't list the files at all.

Not every file is text. A picture (PNG, JPEG, GIF, WebP, HEIC, TIFF, ICO, SVG) is shown fitted to the pane — pinch or ⌘-scroll to zoom, double-click to fit again; a video (MP4, MOV, M4V) or a sound (MP3, M4A, WAV, AIFF, FLAC) plays with the system's controls, full screen and Picture in Picture; a PDF pages through; and an HTML page is rendered, reading its stylesheets and pictures from the checkout around it. A page or an SVG has **Page** / **Source** (**Picture** / **Source**) to switch to its text and edit it; saving a page shows it again as saved. The bar's ↗ opens the file in its own app (Preview, QuickTime, your browser), and a page's 🌐 opens it in a browser tab. On another machine the file is fetched into the app's cache first, with its progress shown (`fs.transfer.v1`, up to 512 MB; a page there gets its own file only, not the files beside it).

## Browser tabs

**File → New Browser Tab** (⇧⌘B) opens a web page in a tab beside the agents, as a terminal or a branch's changes are — split it, move it, close it with ⌘W. Type in the address bar: a port on this computer (`localhost:3000`, `127.0.0.1:8080`) or an address on your network goes over http, since that is what a dev server speaks; anything else with a dot over https; a full address as it is. Back, forward and reload are beside it (or swipe), a page that fails to load says why with **Try Again**, links that would open a window open in the same tab, and the tab is named by the page's title. The compass opens the page in your own browser, for the extensions, sign-ins and devtools that live there — though **Develop → Inspect** works here too, as in Safari. A port in a pane's header opens here.

The **Sessions** row of a project opens its saved conversations in a tab of their own: every agent's, the newest first, any interrupted by a restart above them and starred ones next, each with its agent, title, branch and how long ago. Search narrows them by title, branch or agent, and from three letters looks inside the conversations too (`session.search`), each match with the words around it. **Resume** (or a double-click) starts the agent on that conversation again in a pane; one already running says **open**, and **Open** goes to its pane; **Resume N interrupted** brings back every conversation a restart cut off. The star on a row keeps it to find again — conch's mark, not the agent's. A row's right-click menu also has **Hand off to ▸**, which writes the conversation out where it was and starts another agent there to read it and carry on. The bin on a row deletes the conversation where its agent keeps it, after asking.

## Commits

**Commit graph** on a project's menu opens its history in a tab of its own: every branch and tag of the repository, newest first, as `git log --graph` draws it — each commit a dot on its branch's lane, a lane coloured for its branch from the theme, merges where lanes join — with its short hash, its branches, remote branches and tags as chips (the checked-out one as **HEAD → name**), its subject, author and how long ago. **Show in commit graph** on a branch's menu opens it at that branch's newest commit. The newest 300 are read first; **Show older commits** reads 300 more, up to 2000. It reads again when git moves (a commit, a push, a pull request merged on GitHub, whose base conch then fetches), and ↻ reads it again at any time, asking GitHub about the pull requests then too rather than at the next minute; opening the graph or a branch's git tab asks as well. Right-click a commit to copy its hash or subject, or to view the changes on a branch that points at it. The field at the top finds commits by hash, subject or author, dimming the rest. A click on a commit shows it on the right — its author, its whole message, its parents and the files it changed, each opening its diff there; shift-click another to compare the two, every commit between them and what they change together (**Done** goes back to one). Showing a commit needs `project.commit.v1`. A machine's server needs `project.log.v1` for it: an older one says so, and reloading that server brings it.

## Starting agents and tasks

**File → New Task…** (`⌘N`), or **New task…** on a project's or branch's menu, opens a sheet for a prompt, the agent to give it to and, if you like, the branch's name — [`conch task`](/docs/cli#task) from a window: the server makes a branch and a worktree of its own and starts the agent there with your prompt, in a tab of its own. In a folder that isn't a git repository the agent works in the folder itself. **Issue** picks one of the project's open GitHub issues to work on — its title and body are the prompt, and anything typed is added to it — and **When** starts it later rather than now: a time (`14:05`, `+30m`, `tomorrow 9:00`), `every 1d` for a task that comes back on a branch of its own each time, `queue` to wait until fewer agents are running in the project, or `after BRANCH` to start once that work has finished, on top of it. Later is kept by the server and starts with conch closed too; it is `conch task -at`/`-every`/`-queue`/`-after`/`-issue`. **File → Start Agent** (`⇧⌘N`) starts an agent where the focused pane is.

Right-clicking a row in the sidebar gives its menu, as `m` does in the TUI:

| Row | Menu |
| --- | --- |
| Agent, terminal | Open · Rename… · Prompt… (an agent: a message typed in and submitted for you) · Start an agent here ▸ · New terminal here · View changes on its branch · Alert when it goes quiet and Alert on output (a running terminal; ✓ when on) · Close (an agent asks first; its conversation stays in Sessions) |
| Branch | View changes · Start an agent on this branch ▸ and Open terminal on this branch (when it is checked out) · New task in project… · Show in commit graph · Open pull request (when it has one) · Copy branch name · Remove worktree… (keeps the branch; a worktree with uncommitted work is not removed) · Delete branch… (with its worktree, after saying what that loses — uncommitted files, commits in neither the base nor its upstream — as the server's own dry run counts it; never the base or the main checkout's) |
| Project | New task… · Start an agent in project ▸ · Open terminal in project · Commit graph (a git repository) · Copy path |
| Machine | Start an agent ▸ (in the home directory, in no project) · New terminal · SSH to a host… (this computer) · Add project… · Add machine… · Reconnect · Reload server (its panes keep running) · Upgrade conch there and Remove machine… (another machine; removing asks first, and leaves its agents running there) |
| CLI | Start an agent ▸ · New terminal · SSH to a host… (this computer's) |
| Workspace | Add project… · New task in each project… |

**Saved ssh hosts** — the ones the TUI keeps (`ui.json`) — are listed under this computer's **CLI**, marked *saved*, while no session to one is open; a click logs in to it again with the ssh options it was saved with. **Save this host** on an ssh session's menu keeps it, and **Forget this host** on a saved one lets it go, in the TUI too. Your own folders of the TUI's tree are not shown in the app yet.

**Your own actions** — the `[[actions]]` in `config.toml`, which the TUI puts on its menus — are at the end of the menus of the rows they are for (`on = ["pane", "branch", "project", "machine"]`, all four when unset). Each runs `sh -lc` with its command in a terminal of its own where the row is — a pane's folder, a branch's worktree, a project's checkout, a machine's home — with `CONCH_MACHINE`, `CONCH_PROJECT`, `CONCH_BRANCH`, `CONCH_WORKTREE` and `CONCH_PANE` set, and its terminal stays when the command ends so you can read it (`keep = false` closes it). A branch that is not checked out has nowhere to run one, and says so.

**Broadcast…** — on a machine, CLI, Workspace or project row (**Broadcast to its agents…**), or a project's Agents or Terminals section — sends one message to its running panes, as the TUI's broadcast: a sheet lists them with a tick each, agents first. An agent takes the message as its next prompt and starts ticked, unless it is waiting on an answer (the message would answer it); a terminal runs it as a command, so terminals start ticked only from a Terminals section. ⌘↩ sends, and the status bar says how many took it and why any did not.

**Start an agent ▸** lists the agents installed on that machine. A machine that is offline offers nothing that would start something there; it can still be reconnected, upgraded or removed. A machine whose conch is from an older build than the app's own says **behind** on its row — what it lacks is in the tooltip — and **Reload server** (this computer) or **Upgrade conch there** (another machine) brings it up to date.

## Installing the beta

Each release from v0.1.9 carries **Conch_<version>_macos_arm64.zip** on its [GitHub release page](https://github.com/Amitgb14/conch/releases), with its SHA-256 beside it. It needs a Mac with Apple Silicon and macOS 14 or later, and conch's server comes inside it, so nothing else has to be installed first.

1. Download the zip and open it: it unpacks **Conch.app**.
2. Drag Conch.app into **Applications**.
3. Open it. The beta is signed but not notarized by Apple, so the first time macOS says it can't check it for malicious software: choose **Done**, then open **System Settings → Privacy & Security**, scroll to *"Conch" was blocked* and click **Open Anyway** (on macOS 14, right-click Conch.app → **Open** does the same). After this once it opens as any app does. Or, in a terminal, before opening it: `xattr -dr com.apple.quarantine /Applications/Conch.app`.

To update, download the next release's zip and replace the app; your agents keep running through it, since the server holds them, not the window. A machine you reach over ssh gets the released conch of the same version when the app upgrades it. Report what breaks with **⊙** in the status bar.

## Building it

It needs the Xcode Command Line Tools (Swift 6) and Go. For Ghostty's terminal in the panes it also needs Xcode 26 with its Metal toolchain, and Zig:

```sh
xcodebuild -downloadComponent MetalToolchain   # once, after installing Xcode
brew install zig
macos/ghostty.sh                 # Ghostty's library, from a pinned release → macos/vendor
macos/bundle.sh                  # → macos/build/Conch.app
macos/bundle.sh /Applications    # or straight into Applications
make app-release VERSION=0.1.9   # the beta's zip, for a release: dist/Conch_0.1.9_macos_arm64.zip
```

Without `macos/ghostty.sh` the app builds just the same, with SwiftTerm drawing the panes; the status bar says which.

The app carries its own `conch` inside it, so each pane's `conch attach` is the same build as the window. It looks for conch's server where `conch` does (`$CONCH_SOCKET`, else `conch.sock` in `$CONCH_HOME` or `~/.config/conch`), and when none is running it offers to start one. `CONCH_BIN` points it at another `conch`. Launched with `-background YES` it opens behind whatever is in front and does not make itself active — for a scripted run beside somebody at work. Every sidebar row and tab is a button to accessibility, so VoiceOver (and a script) can open one as a click does.

## What it is built on

The window is AppKit and SwiftUI; the terminal in each pane is [Ghostty](https://ghostty.org)'s — its library (libghostty) from an upstream release, unmodified, with conch's own settings rather than your Ghostty configuration, given the program's own output where the server can (`conch attach -raw`, above) — or [SwiftTerm](https://github.com/migueldeicaza/SwiftTerm) where Ghostty's library has not been built, behind a single seam. Typing goes through macOS's input methods, so Japanese, Chinese and Korean input, dead keys (option-e then e for é), dictation and the character viewer all work; what is being composed is shown at the cursor until it is committed. The left option key is alt; the right one types the characters your keyboard puts there. The code is in `macos/` in the repository: `ConchKit` (the protocol client, the tree, search and layout, with tests run by `swift test`) and `ConchApp` (the window).
