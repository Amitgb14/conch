# Mac app

Conch.app is conch in a native macOS window. It is another client of the same servers the TUI talks to — this computer's and every machine you added — so it shows the same agents and terminals, and closing it stops nothing: the agents keep running, as they do when you close the TUI.

<Callout type="note">

The Mac app is new and is built from source for now (below). Settings, the Sessions view and the git panel are still the TUI's — **conch → Open conch in a terminal** opens it beside the window, and a click on a project's **Sessions** row does too.

</Callout>

## The window

- **The toolbar** holds conch's workspaces (click one to switch; `+` makes one, as in the TUI, which shows it too; double-click or right-click one to name it — `1 main  2 review` — which the TUI shows as well) — each isolated as in the TUI, with tabs of its own and only what is in it: its projects, the panes started in it and what those started, and in the first whatever no other workspace has; an agent or terminal started from the app goes into the workspace on screen, a search field in the middle (⌘K), and how many agents are waiting for you or finished — a click on the waiting count goes to the next one (⌘.).
- **The sidebar** is conch's tree: this computer, then each machine you added (`conch machine add`), each with its projects — agents, branches, terminals and how many saved sessions — and **CLI** for what belongs to no project. Each agent is marked as the TUI marks it, following the same `[ui] icons`: with `icons = "nerd"` the TUI's glyph in the agent's own colour (Claude's asterisk, Codex's six-fold mark…) from a Nerd Font on the Mac, or an SF Symbol of the same shape without one; otherwise a dot in the agent's colour, the mock's, or nothing for `off` and, at the right, a pill while it is **working**, **waiting** for you or **done**; a pane that ended says **exited**. A machine or project row counts what is working (blue), waiting (amber) and done (green) in pills; a project has Finder's folder, a branch git's branch mark (from a Nerd Font when there is one) — in the accent when it is checked out in a worktree of their own, muted when not — with its pull request and how far ahead it is, and Sessions a clock. The pane you are in is the row with the accent behind it, and the row under the pointer is tinted. Another machine is reached as the TUI reaches it, through [`conch machine bridge`](/docs/cli#machine); one that cannot be reached says **offline**, with why on hovering, and is tried again every half minute. A sandbox is listed with its provider (`sandbox · daytona`) and says **stopped** while it is; the app never starts one (`conch sandbox start` does) and looks again every five minutes. Rows fold as they do in the TUI — the same rows open, read from its `ui.json` — and what you fold or open here is remembered by the app without changing the TUI's. A folded machine shows the dots of the agents on it. A click opens a pane; a click on a branch opens its changes (below). Drag the sidebar's edge to make it wider or narrower; the width is remembered.
- **On opening**, the window shows the tabs the TUI is showing (each machine's, as its server keeps them), a tab of three panes as one tall beside two stacked — and gives none of them the keyboard, so no key reaches an agent until you click a pane.
- **Tabs** along the top, the one on screen underlined. A pane is shown in one place: opening it again goes to where it is.
- **Splits** sit side by side as cards with a gap between them, each with a header saying which agent it is, its branch and its state — with how long it has been working. A terminal in a checkout that has been given ports shows the first, `CONCH_PORT` (`:4317`); on this computer a click opens it in the browser. The focused one has the accent border. The tab bar ends with where the tab on screen is (`api · local`).
- **The status bar** says where the keyboard is (**PANE**, or **TREE** when no terminal has it) and the keys for there, each as a keycap; each agent plan's use, as a chip with the agent's mark and each window's bar and share (`✱ 5h ▰▱ 36% │ 7d ▰▱ 19%`, amber from 80%, red at the limit; when each resets is in its tooltip) — a click lists every window the agent reported, the 5 hours, the week and any per-model one, with when each resets; conch's version, with which terminal draws the panes in its tooltip; **⚙ Settings**, which opens conch's [settings page](/docs/interface#edit-in-browser) in the browser (`conch config web`; an open TUI takes in what you save, and the app's theme follows it unless you picked one); and `▁▃▆` in the corner, the memory and CPU conch uses on this computer — the app, the server and each pane with everything running in it — sampled every two seconds while it is open, as the TUI's is.
- **Themes.** **View → Theme** has conch's fifteen themes and three light ones (GitHub Light, Solarized Light, Catppuccin Latte). The first item, **Same as conch**, follows `[ui] theme` in conch's settings, so the window matches the TUI until you pick another; your choice is remembered. A theme colours everything, the terminals in the panes included. In a light theme the terminals keep their usual sixteen colours, so a program's yellow can be faint on white.

Each pane is a real terminal running [`conch attach`](/docs/cli#attach), so an agent looks exactly as it does in the TUI or any terminal.

## A branch's changes

A click on a branch opens its changes in a tab of their own, as `enter` on a branch does in the TUI. The header says the branch, the base it goes into, how many lines it adds and removes, how far it is ahead, and its pull request with its checks. On the left:

- **Uncommitted** — what is changed in the branch's worktree and not yet committed (`M` changed, `A` added, `D` deleted, `?` new and untracked, `U` a conflict), each with its `+`/`−`.
- **Committed on the branch** — what its commits change against the base, for a branch with a worktree.
- **Commits** — the branch's commits.

A file shows its diff on the right, with line numbers on both sides. While an agent works in the worktree the list follows it: a file just written is marked for a few seconds and the open diff reads again. The buttons along the top:

- **Agent or terminal** — the branch's agent, or the terminal already in its worktree (one is started there only if there is none).
- **Commit…** — commits every uncommitted change, with the message you type.
- **Push**, and **Open pull request** (or update it), which opens the pull request in your browser.

Hunks, marking files for a commit, comments and merging are still the TUI's (`b` on the branch there).

## Answering an agent without opening it

An agent waiting for you shows its question under its row in the sidebar, with its choices as buttons — *Yes*, *Yes, and don't ask again*, *No* — and the same buttons along the top of its pane. The one the agent's own cursor is on is highlighted. A click picks it: conch moves the agent's cursor there and presses Enter, exactly as the [phone](/docs/phone) does, and refuses an answer to a question that has changed since it was shown. An agent whose choices conch cannot read off its screen offers **Open to answer** instead.

## Starting agents and tasks

**File → New Task…** (`⌘N`), or **New task…** on a project's or branch's menu, opens a sheet for a prompt, the agent to give it to and, if you like, the branch's name — [`conch task`](/docs/cli#task) from a window: the server makes a branch and a worktree of its own and starts the agent there with your prompt, in a tab of its own. In a folder that isn't a git repository the agent works in the folder itself. **File → Start Agent** (`⇧⌘N`) starts an agent where the focused pane is.

Right-clicking a row in the sidebar gives its menu, as `m` does in the TUI:

| Row | Menu |
| --- | --- |
| Agent, terminal | Open · Rename… · Prompt… (an agent: a message typed in and submitted for you) · Start an agent here ▸ · New terminal here · View changes on its branch · Close (an agent asks first; its conversation stays in Sessions) |
| Branch | View changes · Start an agent on this branch ▸ and Open terminal on this branch (when it is checked out) · New task in project… · Copy branch name |
| Project | New task… · Start an agent in project ▸ · Open terminal in project · Copy path |
| Machine, CLI | Start an agent ▸ (in the home directory, in no project) · New terminal |
| Workspace | New task in each project… |

**Start an agent ▸** lists the agents installed on that machine. A machine that is offline offers nothing that would start something there.

## Keys

| Keys | |
| --- | --- |
| `⌘K` | search: agents, terminals, projects, task branches, files and commands, waiting agents first; a file opens in that machine's `$EDITOR`, in a terminal tab in its checkout |
| `⌘N` | a new task: a prompt, an agent, a branch and worktree of its own |
| `⇧⌘N` | start an agent where the focused pane is |
| `⌘T` | a new terminal tab, in the focused pane's folder |
| `⌘D` / `⇧⌘D` | a new terminal split right / down |
| `⌘W` | close the split — the pane keeps running, and is in the sidebar to open again |
| `⌘1`–`⌘9`, `⇧⌘]` / `⇧⌘[` | go to a tab, next / previous tab |
| `⌘.` | the next agent waiting for you, then the ones that finished |
| `⌃⌘S` | show or hide the sidebar |
| `⌘0` | the sidebar takes the keyboard (so does a click on a row that is not a pane): `↑` `↓` (or `k` `j`) move, `←` folds or goes to the row above it, `→` unfolds or goes in, space folds, `⏎` opens — going into a pane, a branch's changes — and `t` a task, `c` an agent, `n` a terminal, each where the row is, `x` closes a pane |

Everything else you type goes to the focused pane.

## Building it

It needs the Xcode Command Line Tools (Swift 6) and Go. For Ghostty's terminal in the panes it also needs Xcode 26 with its Metal toolchain, and Zig:

```sh
xcodebuild -downloadComponent MetalToolchain   # once, after installing Xcode
brew install zig
macos/ghostty.sh                 # Ghostty's library, from a pinned release → macos/vendor
macos/bundle.sh                  # → macos/build/Conch.app
macos/bundle.sh /Applications    # or straight into Applications
```

Without `macos/ghostty.sh` the app builds just the same, with SwiftTerm drawing the panes; the status bar says which.

The app carries its own `conch` inside it, so each pane's `conch attach` is the same build as the window. It looks for conch's server where `conch` does (`$CONCH_SOCKET`, else `conch.sock` in `$CONCH_HOME` or `~/.config/conch`), and when none is running it offers to start one. `CONCH_BIN` points it at another `conch`.

## What it is built on

The window is AppKit and SwiftUI; the terminal in each pane is [Ghostty](https://ghostty.org)'s — its library (libghostty) from an upstream release, unmodified, with conch's own settings rather than your Ghostty configuration — or [SwiftTerm](https://github.com/migueldeicaza/SwiftTerm) where Ghostty's library has not been built, behind a single seam. Typing goes through macOS's input methods, so Japanese, Chinese and Korean input, dead keys (option-e then e for é), dictation and the character viewer all work; what is being composed is shown at the cursor until it is committed. The left option key is alt; the right one types the characters your keyboard puts there. The code is in `macos/` in the repository: `ConchKit` (the protocol client, the tree, search and layout, with tests run by `swift test`) and `ConchApp` (the window).
