# Sessions

Agents save their conversations; conch lists them per project so you can resume any of them in the right folder. It also remembers agents that were running when the server stopped.

## Saved conversations

Every project has a **Sessions** section in the tree. Select it to list, on the right, the conversations agents saved for the project and its worktrees — Claude Code, Codex, Gemini CLI, OpenCode and Devin — newest first, with the agent, title, branch, what it used and its age:

```text
Sessions · api        enter resume · / search · s share · d delete · a agent
4 saved · all agents · ⚠ 1 interrupted (I resumes all, x dismisses)

▸ ⚠ Claude Code  Fix the flaky login test  fix-login · interrupted · $1.40 · 2h
  ● Codex        Add rate limiting             rate-limit · open · 3.0k out · 5m
  · OpenCode     Refactor config                             main · $0.12 · 1d
  · Gemini CLI   Explain the auth flow                                main · 3d
```

What a session used comes from the agent's own store, so it differs by agent: Claude Code and OpenCode record a cost, Codex the tokens it generated, and Gemini CLI neither — that row simply says nothing rather than showing `$0.00`. Costs are read from the end of the store, so listing stays fast on long conversations.

conch reads the agents' own session stores and never changes them (except `d`, which deletes one after asking); on remote machines the server there lists its sessions.

## Resuming a session

`enter` (or a click on the selected row) resumes a session in its folder with the agent's own resume option:

| Agent | Resume option |
| --- | --- |
| Claude Code | `claude --resume` |
| Codex | `codex resume` |
| Gemini CLI | `gemini --resume` |
| OpenCode | `opencode --session` |
| Devin | `devin -r` |

Devin keeps its sessions in a database of its own, so conch lists them by asking its CLI (`devin list`) in each folder, and `d` deletes one with `devin rm`. Devin conversations can't be searched inside or shared with another agent yet; their titles and IDs still match `/`.

Asking another program takes a moment, and a slow or signed-out one used to hold up the whole list. It no longer does: the list waits about a second and a half for it, then shows the agents whose sessions are files on disk and fills the rest in a moment later.

`Y` opens a conversation to read and copy from — and `Y` on an agent in the tree opens the one it is writing now. It opens on the newest part. Scroll with the wheel or `↑` `↓`, a page at a time with `pgup` `pgdn`, and jump with `g` (top) and `G` (bottom, also `home` and `end`). Drag over the part you want — dragging past the top or bottom keeps scrolling — and releasing copies just that; `a` copies all of it, `esc` closes. What is shown is the conversation as text: escape sequences in it (people paste terminal output into agents) are taken out, so nothing the transcript holds can move your cursor or reach your clipboard as an escape. This is how a long answer is taken out of an agent: an agent draws on the alternate screen, which keeps no scrollback, so dragging over its pane can only ever reach what is on screen.

`●` sessions are already open and `enter` shows their pane. `a` filters by agent, and `R` reloads the list.

## Searching

`/` searches the list as you type: titles, agents, branches and session IDs match at once, and a moment after you stop typing the server searches inside the conversations too — what you asked and what the agents answered, not tool output. A conversation match shows the text around it:

```text
/ cross compiler  2 found

▸ · Claude Code  Deploy fails on arm64  “…The cross compiler is missing. Install…”   main · 2d
  · Codex        Release script         “…needs a cross compiler for linux/arm64…”  main · 5d
```

Every word must appear. `enter` keeps the results and returns to the list keys, `esc` clears the search, `ctrl+u` empties it.

## Sharing a session with another agent

`s` hands a conversation to a different agent, so it can pick up where the other left off:

- **Start an agent with it** — Claude Code, Codex, Gemini CLI or OpenCode starts in the session's folder.
- **Send to a running agent** — any agent already running in the project gets it as its next message.
- **On another machine** (`o`) — pick a project on another online machine, then an agent to start there or one already running in that project.

The [brain](/docs/brain#handing-work-to-another-agent) does the same from a plain request, such as _"hand the auth thread to Codex"_, for the conversation of an agent that is running.

conch writes the conversation — the messages, without tool calls or their output — to `.conch/handoff/<agent>-<session>.md` in the session's folder and asks the agent to read it, summarise what was done and what remains, and continue. `.conch/` is added to the repository's local `.git/info/exclude`, so it never shows up as a change. Very long conversations keep the first request and the latest messages.

### On another machine

The other machine can't read this one's session files, so conch asks this machine's server for the conversation and sends the document to the other one, which writes it to `.conch/handoff/` in that project and tells the agent which machine it came from. It goes into the checkout of the session's branch when the project there has one, otherwise into the project's folder.

Only the conversation moves, not the code: push the branch and check it out on the other machine first if the agent needs the changes. The agent's own session isn't copied either, so it can't be resumed there with the agent's resume option. Both servers need a build that has this; an older one says to reload it.

## Interrupted runs

conch remembers which agents are running. When its server stops — `conch server stop`, a crash, a reboot — those agents are marked `⚠ interrupted` in Sessions (and counted in the tree) for a week. `I` resumes all of them, `x` dismisses one.
