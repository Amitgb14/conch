How an agent in conch starts other agents — a reviewer, a tester, a second opinion — prompts them, waits and reads their answers, each helper in its own pane and branch.

## Setting it up

The agents learn how from six skills conch carries. Install them once per machine.

```sh
conch agent skill            # shows where it would write
conch agent skill -apply     # writes them
```

Or `i` on a pane then `S`, or `,` → **Agents** → **conch's skills…**. In the Mac app: **Settings → Skills & MCP servers**. In Claude Code they are also a plugin (pick one way, not both):

```
/plugin marketplace add Amitgb14/conch
/plugin install conch@conch
```

## Asking an agent for a second opinion

Start an agent (`c`) and ask in plain words. It starts a helper as a task on its own branch, waits, reads what it wrote and tells you. If the helper asks a question, the agent tells you which pane is waiting.

**How:** _"Get a second opinion on the change on this branch from another agent, and tell me what it found."_

## A team, a review loop, a factory

Ask for the other skills the same way, or by name as a command in Claude Code.

| Ask | Skill |
| --- | --- |
| _"Have Claude and Codex each try the parser fix, and tell me which one to keep."_ | conch-team |
| _"Get this branch reviewed by Codex and have the fixes made until the review is clean."_ | conch-review |
| _"Open the pull request for this branch and merge it once CI is green."_ | conch-ship |
| _"Take issue 123 from build to a merged pull request."_ | conch-factory (`/conch-factory 123`) |

## Who started what

A pane an agent started is listed under it, and the agent shows **⑂2** (amber **⑂2!** when one waits).

```
Agents
  ▾ claude                      ⑂2
      ↳ reviewer
      ↳ tester
```

### Claude's own subagents

Claude Code's own subagents are listed under it too, with their task and kind, while they run. `enter` opens the agent running them. What an agent [left running](/docs/agents#left-running-in-the-background) is listed under it the same way, marked ⟳.

## From the tree

`m` on an agent's pane → **Prompt…** sends it a message, and conch tells you once when that work ends.

## Giving helpers files that aren't committed

A helper's worktree holds only committed files. Add a [local files](/docs/tasks#local-files-in-worktrees) pattern so conch copies yours in, or name the file's absolute path in the prompt.

## Doing it yourself

The agents use plain `conch` commands, so a script can too:

```sh
conch task -name reviewer -agent codex -base "$(git branch --show-current)" \
  "Review this branch against main. Write findings to REVIEW.md."
conch wait -state done,waiting -timeout 30m reviewer
conch agent prompt -wait -timeout 30m reviewer "Now check the error handling too."
conch read reviewer
conch close reviewer
```

`conch agent prompt` exits `0` when the turn ended, `3` when the agent waits for an answer (nothing typed), `124` on timeout. See [pane names](/docs/cli#pane-names).

## Through MCP instead of the command line

`conch mcp` offers the same work as MCP tools: `list`, `read`, `start`, `prompt`, `wait`, `task`, `rename`.

**How:** `conch agent library mcp`, then `conch agent library apply`, and restart the agent.

### Three reviewers at once

A lead agent can run several reviewers through the tools without a shell command:

```jsonc
task   {"prompt":"review auth.py",    "branch":"review-auth",    "agent":"claude", "name":"auth"}
task   {"prompt":"review billing.py", "branch":"review-billing", "agent":"codex",  "name":"billing"}
wait   {"pane":"auth", "state":["idle","waiting"], "timeout_seconds":1800}
prompt {"pane":"auth", "text":"Write what you found to FINDINGS.md, worst first."}
read   {"pane":"auth", "tail":20}
```

## What an agent may do

An agent may start panes and tasks and read anything, but change only its own work: panes it started, panes in its project, and that project's branches. Anything else is refused with `out_of_scope` and a reason. The TUI and your own terminals are never limited.

Agents may pick which agent to start and its `--model`, nothing more, and type only into panes running an agent, never a shell. To allow more:

```toml
[agents]
unrestricted_launch = true
```

`conch -m MACHINE` from an agent's pane keeps the same limits on the other machine, held there by that machine's own `unrestricted_launch`.
