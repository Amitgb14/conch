# Tasks and worktrees

How to give each agent its own branch and worktree, finish its work, and set those worktrees up.

<TaskFlow />

## Tasks

A task is an agent on its own branch and git worktree (`<repo>.worktrees/<branch>`), so parallel agents never step on each other.

**How:** `t` on a project, or:

```sh
conch task -cwd ~/src/api "Add a health check endpoint"
conch task -issue 12                       # from a GitHub issue, via gh
conch task -sandbox daytona "…"            # in a sandbox of its own
```

`-agent`, `-branch` and `-base` choose the agent and branches; see the [CLI](/docs/cli#task). Outside a git repository the agent starts in the folder, with no branch.

## Finishing a task

Finish a branch from its changes view (select it, `tab`) or its menu (`m`). The header always names the next key.

<TuiShot id="diff" title="Changes view" caption="A branch's changes, with the next step in the header." />

| Key | What it does |
| --- | --- |
| `space`, `c` | Mark files (or hunks in a diff), then commit them — or everything when none are marked |
| `P` | Push |
| `p` | Push and open a pull request with `gh` |
| `M` | Merge into the base, squashed by default |
| `D` | Remove the worktree and branch, after showing what is lost |

From a shell: `conch branch commit | push | pr | merge | discard` ([CLI](/docs/cli#branch)).

## Cleaning up worktrees

`W` on a project lists every worktree besides the main checkout, with what removing it would lose and why it looks finished (merged, pull request closed, folder gone).

**How:** finished ones come ticked; `space` ticks others, `a` toggles the finished ones, `enter` reviews, `y` confirms. From a shell: `conch worktree ls | clean`.

## Several attempts at one task

Try one prompt several times, each attempt on its own branch, and keep the best.

```sh
conch task -agent claude,codex "Add a health check endpoint"   # one each
conch task -n 3 "Fix the flaky login test"                     # three, same agent
```

In the task dialog, fill **Agent** with a list and **Attempts** with a number.

<Callout type="note">Three attempts use three times the plan window.</Callout>

### Comparing them

`A` on an attempt's changes shows the attempts side by side.

**How:** `enter` opens a diff, `M` merges, `D` discards, `x` keeps the selected one and discards the rest, `t` runs a command such as `go test ./...` in every attempt and shows `passed` or `failed`.

## Later, and on a schedule

The server runs scheduled tasks with conch closed.

```sh
conch task -at 02:00 "Upgrade the test framework and fix what breaks"
conch task -every daily -at 07:00 "Bump the dependencies and run the tests"
conch task -queue "Add rate limiting to the login endpoint"    # starts when fewer than 3 agents run
conch task -after api/model "Add a REST endpoint for invoices" # starts from that branch once it is done
conch schedule            # list; conch schedule rm ID removes one
```

In the task dialog, the **When** field takes `queue`, `after api/model` or a time. For an agent stopped at its plan limit, `C` in the [review queue](/docs/interface) resumes it after the reset.

## Local files in worktrees

A new worktree gets copies of the main checkout's gitignored local files — `.env`, `.env.*`, `.envrc`, `.claude/settings.local.json`, `CLAUDE.local.md`, `.mcp.json`, `AGENTS.override.md`, `.gemini/.env` — so the agent has your settings.

**How:** `F` on a project changes the patterns, or:

```sh
conch project files ID PATTERN...   # set
conch project files ID -reset       # defaults
conch project files ID -none        # none
```

## Setup and ports in worktrees

A **setup command** runs in every new worktree, in a terminal named `setup` beside the agent.

**How:** `F` on a project, or:

```sh
conch project setup ID 'npm ci && cp .env.example .env'
conch project setup -none ID
```

It can read `CONCH_WORKTREE`, `CONCH_BRANCH`, `CONCH_ROOT` and `CONCH_PROJECT`.

### Ports

Each checkout gets ten ports of its own, starting at `$CONCH_PORT`, so two dev servers don't fight over one port. `L` on a branch opens `http://localhost:$CONCH_PORT`.

```sh
npm run dev -- --port $CONCH_PORT
```

## Agent setup

`i` on a project, branch or pane shows what each agent loads there, a tab per agent: instructions, skills, commands, MCP servers, plugins, hooks conch added, and warnings. In a worktree it lists local files that are missing; `c` copies them. `S` installs conch's own skill.

**How:** `i`, or `conch agent setup [-agent NAME] [-copy] [-json] [DIR]`.

## One setup, every agent

`s` in the setup view gives the open agent's instructions, skills and MCP servers to the other agents in this checkout, each where that agent looks. It shows the plan first, never copies secrets, and leaves hand-written files alone. `u` undoes it.

```sh
conch agent sync                                 # show the plan
conch agent sync -from codex -to claude,gemini
conch agent sync -apply
conch agent sync -undo
conch agent sync -user -apply                    # your home, not a checkout
```

The home version is also in Settings → **Agents** → **Your own setup…**.

## Shared MCP servers and skills

The library keeps MCP servers and skills in conch, each ticked for the agents that should have them. Applying writes them into each agent's own configuration; unticking takes them out.

<Shot name="desktop-skills" alt="Skills & MCP Servers in Conch.app's Settings" caption="The library in Conch.app." />

**How:** Settings → **Agents** → **Shared MCP servers & skills…** (in the [Mac app](/docs/mac-app), **Settings → Skills & MCP servers**), or:

```sh
conch agent library                                        # a column per agent
conch agent library import claude
conch agent library add -to codex,devin -env GITHUB_TOKEN='${GITHUB_TOKEN}' github -- npx -y @modelcontextprotocol/server-github
conch agent library skill anthropics/skills/skills/pdf      # from GitHub
conch agent library apply
conch agent library undo
```

Values must refer to variables (`${TOKEN}`); Conch.app can keep a token in the Keychain; a plain one briefly shows on Claude's command line to others on the machine.
