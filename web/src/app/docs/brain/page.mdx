# Brain

How to ask conch for work in plain words, approve the plan it proposes, and get summaries of what agents are doing.

## Asking

Say what you want; the brain turns it into a plan of conch actions — start tasks, message agents, hand work over — using your own agent login or API key.

**How:** press `:` (or click **✦ Ask**), or `conch ask [-y | -n] [-model] "…"` from a shell.

- _"start 3 agents on api: fix the flaky login test, add rate limiting, update the README"_
- _"tell the agent on fix-login to also cover the logout path"_
- _"what is waiting for me?"_

`↑` `↓` choose a suggestion, `enter` asks, `tab` fills the box, `ctrl+p` `ctrl+n` recall earlier requests, `esc` closes.

## Without the model

Requests that mean only one thing are planned at once, with no model call — even with no provider set up.

| Request | Plan |
| --- | --- |
| _"show codex"_ | Show that pane |
| _"close the zsh terminal"_ | Close it |
| _"tell codex to run the tests"_ | Send _Run the tests_ |
| _"tell everyone to commit"_ | Broadcast to every agent |
| _"what is waiting?"_ | List those agents |

**How:** press `m` on the plan to send it to the model instead.

## Approving the plan

Each proposed action has a checkbox; invalid ones are marked and skipped.

```text
✦ Plan
  1. Hand the conversation of fix login on this computer to codex (a new pane)
  enter run · space tick · esc cancel
```

<Callout type="note">**Nothing runs until you press enter.**</Callout>

## Handing work to another agent

Say who should take over. conch writes the conversation to a handoff file and starts the other agent on it, or gives it to one already running — the same as `s` in [Sessions](/docs/sessions).

**How:** _"hand the auth thread to Codex"_, _"let Gemini continue what Claude is doing on fix-login"_.

## One message to several agents

Each agent gets the message once, as its next one — like `B` in the tree ([Agents](/docs/agents)).

**How:** _"tell every agent in api to run the tests before committing"_.

## Finding what needs you

`/` then `!` keeps only the agents waiting for an answer, on every machine. `!` alone jumps to the next one; `esc` clears.

## Summaries

`S` on an agent asks for a one-line summary of what it is doing and what it needs from you, shown in its title bar.

**How:** `S`, or Settings → Brain → _Summarise agents_ to do it whenever an agent finishes or starts waiting. Each summary is a small model request that sends the agent's screen to the provider.

## Configuration

Choose a provider in Settings → Brain, or in `config.toml`:

| Provider | Uses |
| --- | --- |
| `claude` _(default)_ | the Claude Code CLI with your Claude login |
| `anthropic` | the API with `$ANTHROPIC_API_KEY` |
| `openai` | any OpenAI-compatible endpoint, such as Ollama |

```toml
[brain]
provider = "claude"
model = ""            # provider default
summary_model = ""
summaries = false     # automatic summaries
```

Other keys (`base_url`, `api_key_env`, `command`, `no_fast_path`) are on [Configuration](/docs/configuration).
