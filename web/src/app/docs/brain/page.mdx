# Brain

The brain turns a request in plain words into a plan of conch actions — start tasks, message agents, answer questions — and summarises what agents are doing. It uses your own agent login or API key.

## Asking

Press `:` (or click **✦ Ask**) and say what you want:

- _"start 3 agents on api: fix the flaky login test, add rate limiting, update the README"_ — split into tasks, each on its own branch and worktree with a self-contained prompt
- _"tell the agent on fix-login to also cover the logout path"_ — a message typed into that agent
- _"hand the auth thread to Codex"_ — the Claude conversation in that pane is written to a handoff file and Codex is started on it, [as `s` does in Sessions](/docs/sessions#sharing-with-another-agent)
- _"tell every agent in api to run the tests"_ — one message to several agents at once, [as `B` does in the tree](/docs/agents#broadcast)
- _"what is waiting for me?"_ — an answer, no actions

From a shell, `conch ask [-y | -n] "…"` does the same: `-y` runs the plan without asking, `-n` only shows it.

## Approving the plan

The brain sees every connected machine, its projects, branches and agents (with their states and summaries) and proposes a plan. Each action is listed with a checkbox; invalid ones (an unknown project, an agent that isn't installed, an offline machine) are marked and skipped.

It can propose these actions:

| Action | What it does |
| --- | --- |
| Start a task | a new branch and worktree with an agent working on a prompt |
| Start an agent | an agent in a project or branch you already have |
| Send | a message typed into one running agent and submitted |
| Share | hand one agent's conversation to another, new or already running |
| Broadcast | one message to several agents on a machine at once |
| Show, Close | focus a pane, or close it (only when you ask) |

A broadcast and a share only ever reach agents: a terminal would run the text as a shell command, so conch skips it and says so. Sharing needs the agent to have saved a conversation; until it has, the action is refused rather than starting an agent with nothing to read.

<Callout type="note">

**Nothing runs until you press enter.**

</Callout>

## Summaries

`S` on an agent asks for a one-line summary — what it is doing and what it needs from you — shown in its title bar and on the project page, and given to the planner.

Settings → Brain → _Summarise agents_ does this on its own whenever an agent finishes or starts waiting.

<Callout type="warning">

Each automatic summary is a small model request, and the agent's visible screen is sent to the provider.

</Callout>

## Providers

Choose a provider in Settings → Brain, or with `[brain]` in config.toml:

| Provider | Uses | Default models |
| --- | --- | --- |
| `claude` _(default)_ | the Claude Code CLI headless (`claude -p`, no tools, MCP servers, settings or session history) with your existing Claude login | sonnet · haiku for summaries |
| `anthropic` | the API with `$ANTHROPIC_API_KEY` | claude-sonnet-5 · claude-haiku-4-5 |
| `openai` | any OpenAI-compatible endpoint: `base_url = "http://localhost:11434/v1"` for Ollama | set `model` |

## Configuration

```toml
[brain]
provider = "claude"
model = ""            # provider default
summary_model = ""    # a small, fast model by default
summaries = false     # automatic summaries
```

Three more keys are optional:

| Key | Effect |
| --- | --- |
| `base_url` | overrides the API endpoint (`anthropic`, `openai`) |
| `api_key_env` | names the environment variable holding the API key (default `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`) |
| `command` | the `claude` binary for the `claude` provider; empty finds it on `PATH` |

## New providers

New providers implement `brain.Provider` (`Complete` with an optional JSON schema for structured output).
