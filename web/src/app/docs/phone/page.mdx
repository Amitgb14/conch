# Phone

`conch web` lets a phone reach the agents on this machine: see what each is doing, reply to one, and answer the question it is waiting on. It is a small web server that conch runs on your laptop, in front of the same server the TUI talks to. Nothing goes through a service of conch's; the phone reaches the laptop over [Tailscale](https://tailscale.com).

<Callout type="note">

Notifications are built but haven't been seen on a real phone yet. On an iPhone they need iOS 16.4 or later and conch added to the Home Screen.

</Callout>

## Start it

```sh
tailscale serve --bg http://127.0.0.1:8722        # Tailscale's HTTPS in front of the gateway
conch web -url https://laptop.tail1234.ts.net      # listens on 127.0.0.1:8722, for tailscale serve
conch web pair            # a QR code and a one-time code for the phone — or P in the TUI
```

`conch web` starts conch's server if it isn't running, and keeps running in the foreground; stop it with `ctrl+c`. It is a client of that server like the TUI is, so agents keep running whether or not the gateway does.

**It is reachable only over your tailnet.** A paired phone can type into your agents, so this is remote access to your machine. With `-url`, `tailscale serve` is in front and `conch web` listens on `127.0.0.1` only: the Tailscale app can't proxy back to the machine's own tailnet address (on macOS it gets "connection refused"), and nothing on the tailnet should reach the plain-http port directly. Without `-url` it listens on the Tailscale address, and with no Tailscale address it refuses to start. `-listen ADDR` names another address (with a warning unless it is loopback or Tailscale's); `-port N` changes the port.

**Phones need HTTPS.** The device's token travels in a cookie marked `Secure`, which a browser only sends over HTTPS. `tailscale serve` puts HTTPS in front with a certificate for your machine's tailnet name; tell conch that address with `-url`, so the QR code points phones there rather than at the plain address it listens on, and so pages from it count as the gateway's own. Without either, `conch web` prints the two commands to run, with your machine's tailnet name filled in. Pairing from a plain `http://` page is refused with that reason — the browser would pair and then drop the key — except on the laptop itself (`localhost`), which browsers treat as secure. Or give conch a certificate yourself with `-cert FILE -key FILE` (`tailscale cert` makes one).

## The app

The gateway serves the app itself, so it always matches your conch build; there is nothing to install from a store. Open the gateway's address in the phone's browser. **Add it to the Home Screen** (Safari: Share → Add to Home Screen; Chrome: Install app) and it opens like an app, without the browser's bars. It is laid out like the Claude app: warm colours, one conversation at a time, everything else a tap away.

- **Inbox** — what needs you, first. An agent waiting on a question shows the question and its choices right there: tap one to answer without opening anything. Below it, what finished, what is working, what is idle, and your terminals.
- **☰ the drawer** — every agent and terminal on the machine, by project, as Claude lists its chats; ＋ New and Settings at the ends.
- **An agent** — a conversation: its state, the question it asks with its choices as buttons, what it said last, and a composer pinned to the bottom. While it works and the box is empty, the send button becomes **■ stop** (Esc, as at the laptop; needs `full`). A reply is held back while it waits on a question, and it says why.
- **Its terminal** — the whole screen, live, fitted to what the keyboard leaves visible so the prompt and the key row stay in view. **Tap it and type**: the phone's keyboard goes straight to the pane, accents, paste and all. A row of keys rides on top of the keyboard — esc, tab, **ctrl** and **alt** (tap once for the next key, twice to lock), the arrows, shift+tab, `| ~ / -`, and ^C (two taps). **Aa** changes the text size; a wide terminal scrolls sideways. A plain terminal opens straight on its screen.
- **⋯** on an agent or terminal — switch between conversation and terminal, rename it, or close it (two taps).
- **＋** (devices with `full`) — a new **task** (branch, worktree and agent), a new **agent** in a project or your home folder, with an optional first message, or a new **terminal**.

**When the laptop can't be reached** — asleep, or off the tailnet — the app still opens, says so, and shows the agents and terminals as they were when it last heard from the laptop, with the time. It keeps trying and catches up by itself. Questions are not kept on the phone between visits: they can quote a command.

## Pair a phone

```sh
conch web pair                       # reply: see agents, reply, answer questions
conch web pair -permission view      # look only
conch web pair -permission full      # also the terminal's keys and new tasks
```

This prints a QR code and a six-digit code. Point the phone's camera at the QR code: it opens conch with the code filled in, and one tap pairs it. Or open the gateway's address on the phone and type the code. Either way the phone gets a token of its own, kept in a cookie the page's scripts can't read.

**In the TUI, press `P`** in the tree for the same: a QR code and a code, for a phone with `reply`. `v`, `r` and `f` give a new code for `view`, `reply` or `full`; `y` copies the link. The QR code needs about 37 columns by 17 rows, so it shows in an 80×24 terminal; a smaller one shows the code and the address alone. It pairs with this computer's `conch web`, whichever machine is selected in the tree.

The code travels in the link's fragment (`#code=…`), which a browser never sends to a server, so it is in no log.

- A code works **once**, for **5 minutes**. Asking for a new one cancels the old.
- Guesses are limited: a few attempts a minute, and five wrong codes cancel the one outstanding.
- conch keeps only a hash of each token, in `phone.json` in its [directory](/docs/configuration). The file alone doesn't let anyone in.

| Permission | The device can |
| --- | --- |
| `view` | see the agents, their state and their screens |
| `reply` (default) | also send an agent its next message, and pick an answer to the question it asks |
| `full` | also type into terminals, stop an agent, start tasks, agents and terminals, rename and close them |

The permission is checked on every request and on every message over the live connection, not only when the phone connects.

## Devices

```sh
conch web devices        # ID, name, permission, when it was paired
conch web revoke d_7h2k  # cut one off
conch web permission d_7h2k full   # let it type into terminals, without pairing again
```

Revoking takes effect at once: the token stops working, and a running gateway closes the connections that device has open — within a quarter of a second — telling the phone why.

An agent that conch [keeps to its own work](/docs/cli#when-an-agent-runs-these-commands) may not run `conch web pair` or `revoke`: a paired phone acts as you, not as the agent.

## Replying and answering

These are two different things, on purpose.

**A reply** is the agent's next message, as [`conch agent prompt`](/docs/cli#agent) sends it. It is refused while the agent waits on a question — typed in, its Enter would answer the question — and the phone is told the agent is waiting.

**An answer** picks one of the choices of the question an agent is asking. conch reads the choices off the agent's screen — a numbered menu with a cursor on one row — and the phone shows them as buttons. Tapping one moves the cursor to that row and presses Enter; nothing else is sent. The answer carries the ID of the question it was shown for, and is refused if the agent is no longer asking that question, so a tap that arrives late can't answer the next one.

When conch can't read choices — no menu, or no cursor to steer by — the question comes without any. A device with `full` answers it in the terminal, with the key bar; the others at the laptop.

## What it doesn't do yet

- Showing the question in a notification: there is no setting for it, so it is never shown.
- Scrolling back through a terminal's history: the terminal shows the screen as it is now.
- A list of the agents installed on the laptop: the new-task form offers every agent conch knows, installed or not.
- Other machines: a gateway shows the agents of the machine it runs on.

## What is logged

One line per request and per message: its kind, its status and its size. Never a screen, a reply, a question or a token.
